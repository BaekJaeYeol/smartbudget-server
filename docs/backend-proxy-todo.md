## 작업 시작 전 상태

- OCR `POST /api/v1/proxy/ocr`: 라우트와 응답 스키마는 있으나 라우트는 `NotImplementedError`를 발생시킨다. 실제 인증·업로드 검증·외부 호출은 구현되지 않았다.
- 소비 분석 `POST /api/v1/report`: 사용자 인증, 기간의 거래 조회, 단순 집계 문장 생성, 리포트 생성·재생성과 목록·상세 조회·삭제가 구현되어 있다. 외부 LLM 호출은 없다.
- 거래 수정·삭제 시 관련 리포트를 오래된 상태로 표시하지만 거래 생성 시에는 표시하지 않는다.
- [서버 설명서](server.md)의 리포트 스텁 설명은 현재 코드와 다르므로 구현 작업 시 갱신한다.

## OCR 프록시

- [ ] 기존 Document Intelligence의 영수증 모델과 허용 파일 형식·가격·할당량을 확인하고 인증 방식을 결정한다. HEIC 직접 처리 불가 시 변환 등 명세 준수 방식을 정한다.
- [ ] 서버용 엔드포인트와 인증 설정 및 필요한 HTTP·multipart 의존성을 추가하고 `.env.example`과 실행 문서에 설명한다. 실제 비밀값은 저장소에 넣지 않는다.
- [ ] Bearer 인증과 요청 검증을 구현한다. `files` 1~10개, JPEG·PNG·HEIC·PDF, 파일당 최대 10,000,000바이트, 빈 파일·실제 형식 및 미정의 필드를 외부 호출 전에 검증한다.
- [ ] 파일별 OCR 호출에 60초 제한을 적용하고 자동 재시도하지 않는다. 일부 또는 전체 파일이 실패해도 결과를 구성할 수 있으면 입력 순서대로 파일별 결과를 반환한다.
- [ ] 상호·항목·날짜·시간·총액을 계약대로 변환한다. 여러 영수증이 검출된 파일은 실패 처리하고, 여러 페이지 PDF는 하나의 영수증으로 해석한다. 누락 필드는 null 또는 빈 배열로 처리하며 거래는 자동 저장하지 않는다.
- [ ] `Idempotency-Key`를 구현한다. 사용자·작업·키 기준 성공 응답을 24시간 보관하고, 동일 요청 재사용·다른 요청 충돌·진행 중 충돌을 구분한다. 실패 응답은 보관하지 않는다.
- [ ] 1개 및 10개 파일에 대한 시간·메모리·외부 동시 호출 제한을 측정하고 전체 시간 제한과 병렬 처리 수를 결정한다. 동기 요청이 불안정하면 202 기반 비동기 방식 전환을 검토하고 계약을 갱신한다.

## 소비 분석

- [ ] 기존 Foundry의 `gpt-6-luna`가 필요한 API·인증 방식·출력 형식·할당량과 비용에 적합한지 확인하고 사용할 모델과 설정을 확정한다.
- [ ] 외부 LLM 호출과 Markdown 결과 저장을 구현한다. 전체 호출에 60초 제한을 적용하고 재시도하지 않으며, 호출 실패 502·시간 초과 504를 반환한다. 실패 시 기존 리포트는 변경하지 않는다.
- [ ] 수입·지출을 구분해 기간·종류·카테고리별 건수와 합계만 전달한다. 사용자 ID, 상호, 메모, 개별 거래 원문은 전달하지 않으며 지출이 없으면 그 사실을 명시한다. 현재 집계는 카테고리 합계에서 수입과 지출을 구분하지 않는다.
- [ ] 한국 시간 기준 미래 기간과 주간 월요일·월간 1일·연간 1월 1일 시작 조건을 검증한다. 거래가 없을 때 오류 메시지를 OpenAPI 계약과 일치시킨다.
- [ ] 현재 무시하는 `Idempotency-Key`를 구현하고 성공 응답의 24시간 보관, 재사용과 충돌을 처리한다.
- [ ] 사용자·기간별 생성 작업의 동시 실행을 막는다. 자동 생성도 같은 잠금을 사용하고, 사용자·기간별 리포트 하나만 유지되도록 저장 단계와 기존 DB 이전 방식을 검토한다.
- [ ] 거래 생성 시에도 관련 리포트를 `is_stale=true`로 표시한다. 거래 수정·삭제 및 날짜 변경 전후 처리와 생성 중 거래 변경의 경합도 검증한다.
- [ ] 한국 시간 기준 일간·주간·월간·연간 리포트 자동 생성을 구현한다. 거래가 없는 사용자는 건너뛰고 재시작·중복 실행 시 처리 방식을 정한다.
